# Feedback 도메인 기능 명세 (Feature Specifications)

## 1. 유스케이스 목록

| 유스케이스 ID | 기능명 | 주요 주체 | 설명 |
| :--- | :--- | :--- | :--- |
| **UC-FB-01** | 피드백 목록 조회 | 누구나 | 카테고리별 필터링, 최신순/공감순 정렬 및 상태 뱃지 목록 조회 |
| **UC-FB-02** | 피드백 등록 | 누구나(게스트/회원) | 제목, 본문, 카테고리, 닉네임, 비공개 여부를 지정하여 의견 등록 |
| **UC-FB-03** | 공감(나도 필요해요) 투표 | 누구나 | 원하는 기능 제안이나 공감되는 불편 사항에 추천 1회 투표 |

## 2. 세부 사용자 시나리오

### 시나리오 1: 새로운 기능 제안 등록
1. 사용자가 상단 메뉴, 사이드바, 또는 화면 우측 하단의 플로팅 피드백 버튼(FAB)을 클릭한다.
2. `FeedbackWriteModal`이 화면에 뜬다.
3. 카테고리로 **💡 기능 제안**을 선택한다.
4. 제목(예: "워런 버핏 외에 피터 린치 PEG 기준 정렬 기능이 있으면 좋겠어요")과 내용을 입력한다.
5. (비로그인 상태인 경우) 사용할 닉네임을 입력한다.
6. [의견 남기기]를 누르면 `POST /api/feedback`을 호출하고, 토스트 안내("소중한 의견을 남겨주셔서 감사해요!")와 함께 목록 상단에 새 피드백이 추가된다.

### 시나리오 2: "나도 필요해요" 공감 투표
1. 사용자가 피드백 목록을 보다가 마음에 드는 기능 제안 카드를 발견한다.
2. 카드의 `💡 나도 필요해요 (3)` 버튼을 클릭한다.
3. 즉시 버튼이 파란색(`text-[#3182f6]`, `bg-blue-50`)으로 활성화되며 카운트가 `4`로 0.1초 내 즉각 반영된다 (낙관적 UI 업데이트).
4. `POST /api/feedback/[id]/like`가 서버에 비동기 전달되어 영구 반영된다.

### 시나리오 3: 관리자 검토 및 답변
1. 관리자로 로그인한 사용자는 각 카드 하단에 노출되는 `[상태 변경 및 답변]` 버튼을 클릭한다.
2. 상태를 `개발하고 있어요`로 변경하고, 공식 답변(예: "제안해주신 PEG 기준 정렬 필터는 다음 주 정기 업데이트에 반영될 예정이에요.")을 입력한다.
3. [답변 등록하기]를 누르면 `PATCH /api/feedback/[id]/admin`이 호출되어 카드의 상태 뱃지가 파란색 `개발하고 있어요`로 바뀌고 관리자 답변 말풍선이 렌더링된다.
