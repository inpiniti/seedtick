# 토스 디자인 (Toss Design)

토스 스타일의 프론트엔드를 만들기 위한 가이드. 핵심 철학은 세 가지다.

1. **단순** — 한 화면에는 하나의 목적만 (1 thing / 1 page). 복잡성은 사용자가 아니라 시스템이 흡수한다.
2. **명료** — 다음에 무슨 일이 일어날지 항상 예측 가능하게. 버튼 라벨, 문구, 시각 계층이 전부 이 목적에 복무한다.
3. **따뜻함** — 에러·빈 화면·기다림 같은 최악의 순간이 가장 기억에 남는다(피크엔드). 그 순간을 친절하게 설계한다.

UI 코드를 쓰기 전에 이 문서의 토큰과 패턴을 기본값으로 삼고, 문구를 쓸 때는 UX 라이팅 규칙을 통과시키고, 리뷰할 때는 체크리스트로 검사한다.

## 비주얼 시스템

색·그림자·radius를 임의로 정하지 말고 아래 토큰을 기본값으로 사용한다.

### 컬러

| 역할 | 값 | 용도 |
|---|---|---|
| 배경 | `#f7f9fc` (라이트) | 페이지 배경 |
| 서피스 | `#ffffff` | 카드, 시트, 모달 |
| 텍스트 primary | `#191f28` | 제목, 본문 |
| 텍스트 secondary | `#4e5968` | 보조 설명 |
| 텍스트 tertiary | `#8b95a1` | 캡션, 비활성 |
| 구분선 | `#e5e8eb` | border, divider |
| **포인트(primary)** | `#3182f6` | CTA, 링크, 선택 상태 — **화면당 포인트 컬러는 이것 하나** |
| 경고/상승 | `#f04452` | 에러, 삭제, (금융) 상승 |
| 성공/하락 | `#03b26c` | 성공, (금융) 하락 |
| 주의 | `#ff9500` | 대기, 보류 상태 |

- 강조가 필요하면 색을 늘리지 말고 **굵기·크기·여백**으로 해결한다. 한 화면에 강조 색상 3가지 이상이면 잘못 가고 있는 것이다(폰 레스토프).
- 다크 모드를 지원한다면 색을 하드코딩하지 말고 토큰(CSS 변수 등)으로 감싸고, 그래픽은 양쪽 모드에서 잘 보이는 **중간 명도**로 만든다.

### 형태·그림자·타이포

```css
/* 카드 */
border-radius: 16px~24px;           /* 작은 요소 8~12, 카드 16~24 */
box-shadow: 0 2px 8px rgba(0,0,0,0.06);  /* opacity 0.05~0.08, 항상 미묘하게 */

/* 타이포 계층 — 크기보다 웨이트로 계층을 만든다 */
제목: 20~24px bold  ·  본문: 15~17px regular  ·  캡션: 12~13px  (line-height ≈ 1.4~1.5)
```

- 숫자는 항상 **청킹**: `₩74,330` (O) / `74330` (X), `82%` (O) / `0.82` (X)
- 폰트 크기를 px로 고정하지 말고 사용자의 접근성 설정(Larger Text)이 반영될 수 있게 상대 단위나 스케일 함수를 고려한다.

## UX 라이팅 — 5가지 규칙

사용자에게 노출되는 **모든** 문구(버튼, 에러, 빈 상태, 토스트, placeholder)에 적용한다. 상세 규칙과 변환 예시는 [references/ux-writing.md](references/ux-writing.md).

| # | 규칙 | X | O |
|---|---|---|---|
| 1 | **해요체** — 상황 불문 | 삭제되었습니다 | 삭제했어요 |
| 2 | **능동형** — '~었/되' 빼기 | 전송이 완료됐어요 | 전송했어요 |
| 3 | **긍정형** — 안 되는 것 대신 하는 법 | 잔액이 부족해 송금할 수 없어요 | 10,000원을 채우면 보낼 수 있어요 |
| 4 | **캐주얼한 경어** — 과공 금지 | 확인하시겠어요? | 확인할까요? |
| 5 | **명사+명사 금지** — 동사로 풀기 | 계좌 개설 완료 | 계좌를 만들었어요 |

- 다이얼로그의 왼쪽(보조) 버튼은 항상 **"닫기"** — "취소"를 쓰지 않는다.
- CTA 라벨은 누르면 무슨 일이 생기는지 그대로 쓴다: "확인"보다 **"삭제하기", "보내기", "가입하기"**.

## 필수 인터랙션 패턴

### 로딩 — 스켈레톤, 스피너 단독 금지 (도허티 임계: 0.4초 내 피드백)

```jsx
// ❌ 빈 화면 + 스피너만
{loading && <Spinner />}

// ✅ 스켈레톤으로 레이아웃 자리를 잡는다
{loading
  ? [1, 2, 3].map((i) => <SkeletonRow key={i} />)
  : items.map((item) => <ItemRow key={item.id} item={item} />)}
```

- 버튼은 클릭 즉시 인라인 로딩 상태로 전환한다 (`loading` prop).
- 오래 걸리는 작업(업로드, 생성)은 단계별 **진행률**을 보여준다.

### 빈 상태 — 차갑게 두지 않는다 (피크엔드)

```jsx
// ❌ <Text>데이터가 없습니다</Text>

// ✅ 아이콘 + 해요체 안내 + 다음 행동
<EmptyState
  icon="📭"
  title="아직 주문한 내역이 없어요"
  description="첫 주문을 하면 여기에 나타나요"
/>
```

### 에러 — 시스템 탓 말고 다음 행동을 안내

`"에러 발생"` (X) → `"잠시 연결이 어려워요. 조금 뒤에 다시 시도해 주세요."` (O). 성공 순간(완료, 저장)에도 짧은 긍정 피드백(토스트, 체크 애니메이션)을 준다.

### 선택 입력 — 칩/드롭다운 혼용 대신 바텀시트

반복적으로 고르는 항목은 **읽기 전용 선택 박스 → 탭하면 바텀시트 → 단일 선택 리스트(현재 값 체크 표시) → 선택 즉시 닫힘** 패턴으로 통일한다. 같은 유형의 선택 항목은 같은 높이/패딩/chevron 아이콘을 재사용한다.

### 주요 액션 — 하단 고정 CTA

화면의 핵심 액션은 하단 고정 CTA 버튼 하나로. 세이프에어리어 패딩 포함, 키보드가 올라오면 키보드 위에 붙인다. 터치 타깃은 **최소 44px**(권장 48~56px), 인접 버튼 간격 8px 이상(피츠).

컴포넌트별 구현 스펙(버튼·바텀시트·다이얼로그·토스트·리스트·입력 필드 등)은 [references/component-patterns.md](references/component-patterns.md)를 읽는다.

## 다크패턴 금지 — 5가지

이 패턴이 보이면 코드 리뷰에서 반드시 지적한다.

1. **진입 직후 바텀시트/팝업** — 광고·알림 동의 등 초기 인터럽트 금지
2. **뒤로 가기를 막는 인터럽트** — 이탈 방지용 시트/모달 금지
3. **거절할 수 없는 구조** — 모든 유도에는 "나가기/다음에" 선택지 제공
4. **예상 못한 광고 돌출** — 사용 흐름 중간의 전면 광고 금지
5. **불명확한 CTA** — 누르면 무슨 일이 생기는지 라벨만 봐도 알 수 있어야 함

부정적 감정 표현(애원·호소·불쾌감)을 담은 그래픽/문구도 다크패턴이다. 오류가 아닌데 느낌표, 기다릴 필요 없는데 로딩 아이콘처럼 **상황과 어긋난 시각 신호**도 금지.

## 10가지 UX 법칙 — 빠른 체크리스트

UI를 작성한 뒤(또는 리뷰할 때) 아래 표로 검사한다. 각 법칙의 상세 설명과 항목별 체크리스트는 [references/ux-laws.md](references/ux-laws.md).

| # | 법칙 | 핵심 규칙 | 코드 기준 |
|---|---|---|---|
| 1 | 제이콥 | 익숙한 패턴 유지 | 동종 서비스의 표준 화면 구조 |
| 2 | **피츠** | 터치 타깃 ≥ 44px | `paddingVertical ≥ 11` + 간격 8px |
| 3 | **힉** | 선택지 ≤ 7개 | 넘으면 그룹핑/단계 분리 |
| 4 | 밀러 | 청킹으로 정보 묶기 | `₩74,330`, `82%`, 섹션당 5~9개 |
| 5 | 포스텔 | 1 thing / 1 page | 화면당 입력 필드 최소화 + 합리적 기본값 |
| 6 | **피크엔드** | 빈 상태·에러도 따뜻하게 | 이모지 + 해요체 안내 |
| 7 | 테슬러 | 복잡성은 시스템이 흡수 | 기본값 추천, 자동 계산 |
| 8 | 심미적 사용성 | 일관된 토큰 | 이 문서의 컬러·그림자·radius |
| 9 | 폰 레스토프 | 중요한 것 하나만 강조 | 화면당 fill CTA 1개 |
| 10 | **도허티** | 0.4초 내 피드백 | 스켈레톤, 인라인 로딩 |

(**굵은 항목**이 실무에서 가장 자주 위반된다.)
