# 컴포넌트 패턴 — 토스 스타일 구현 스펙

토스 디자인 시스템(TDS)의 컴포넌트 동작을 일반 프론트엔드(React/RN/웹)에서 직접 구현할 때 따르는 스펙.
실제 토스 파트너 환경이면 `@toss/tds-mobile` 패키지를 우선 사용한다.

## Button

| 속성 | 스펙 |
|---|---|
| size | small / medium / large / xlarge — 어떤 크기든 터치 영역 ≥ 44px |
| variant | `fill`(포인트 색 채움, 화면당 1개) / `weak`(연한 배경, 보조) |
| display | inline / block / full(가로 꽉 참 — 하단 CTA용) |
| 상태 | `loading`(인라인 스피너, 클릭 즉시), `disabled` |

- 아이콘 전용 버튼은 `aria-label` 필수.
- 로딩 중 `aria-busy` 적용, 더블 클릭 방지.

## 하단 고정 CTA (BottomCTA)

화면의 핵심 액션을 하단에 고정하는 패턴.

- 세이프에어리어 패딩 포함 (`env(safe-area-inset-bottom)` / RN SafeAreaView).
- 키보드가 올라오면 **키보드 바로 위에** 붙는다.
- 배경에 살짝 그라데이션/배경색을 깔아 콘텐츠와 겹칠 때 가독성 유지.
- 버튼 2개가 필요하면 좌(weak, 보조)/우(fill, 주) 배치 — 주 버튼이 더 넓게.
- 스크롤 방향에 따라 숨김/표시하는 동작은 선택 사항.

## BottomSheet (바텀시트)

선택 입력·추가 정보·간단한 확인에 사용. **모달보다 바텀시트를 우선** 고려한다 (엄지 접근성).

- 딤(dim) 영역 탭, 뒤로 가기로 **항상 닫을 수 있어야 한다**.
- 선택 리스트: 현재 선택값에 체크 아이콘, 선택 즉시 닫힘.
- 헤더(제목) + 리스트/콘텐츠 + (필요시) 하단 CTA 구조.
- 콘텐츠가 길면 시트 내부 스크롤, 드래그로 확장 허용 가능.
- **서비스 진입 직후 자동으로 열지 않는다** (다크패턴).
- 포커스 트랩 적용 (열려 있는 동안 배경 포커스 이동 차단).

## Dialog (다이얼로그)

바텀시트로 부족한 **중요한 확인**에만 사용.

| 타입 | 버튼 | 용도 |
|---|---|---|
| Alert | 1개 ("확인") | 완료·상태 변경 알림 |
| Confirm | 2개 ("닫기" + 행동 버튼) | 파괴적/중요 액션 확인 |

- 왼쪽 버튼은 **"닫기"** ("취소" 금지), 오른쪽은 행동 라벨("삭제하기").
- 파괴적 액션의 확인 버튼은 경고색(`#f04452`).
- 딤 클릭으로 닫기 허용이 기본. 닫으면 안 되는 경우엔 다이얼로그를 살짝 흔들어(위글) 알려준다.
- 열릴 때 배경에 `aria-hidden`, 다이얼로그로 포커스 이동.

## Toast (토스트)

짧은 알림·완료 피드백. 사용자의 흐름을 끊지 않는다.

- 자동 닫힘: 버튼 없으면 **3초**, 액션 버튼 있으면 **5초**.
- 위치: 하단 기본. 하단 고정 CTA가 있으면 **CTA 위에** 뜬다.
- 아이콘(체크 등) + 한 줄 문구 + (선택) 액션 버튼 1개.
- 접근성: `aria-live="polite"` (긴급하면 assertive).

## TextField (입력 필드)

- variant: `box`(기본 사각형) / `line`(밑줄) / `big·hero`(금액 등 주목형 큰 입력).
- 구성: label + 입력 + help(보조 메시지) + 에러 메시지.
- 에러 시: 테두리/라벨 경고색 + **긍정형 안내 문구** ("8자 이상 입력해 주세요").
- `prefix`/`suffix`로 통화 기호·단위 표시 (`₩`, `원`, `%`).
- 지우기(clear) 버튼, 비밀번호 표시 토글은 우측에.
- 고정 형식(전화번호, 인증번호)은 분할 입력 + 자동 포커스 이동.
- 모바일: 용도에 맞는 `inputMode`/`keyboardType` (숫자는 숫자 키패드).

## ListRow (리스트 행)

left(아이콘/이미지) / contents(텍스트 1~3줄) / right(값·화살표·버튼) 3영역 구조.

- 행 전체가 탭 영역 (높이 ≥ 48px 권장), 터치 피드백(살짝 어두워짐).
- 이동 가능한 행은 우측 chevron(>).
- 텍스트: 1행(제목만) / 2행(제목+설명) / 우측 값 정렬 변형.
- 구분선은 연하게(`#e5e8eb`) 또는 여백으로 대체.
- 섹션 헤더(ListHeader): 제목 + (선택) 우측 "전체 보기" 링크.

## Skeleton (스켈레톤)

로딩 중 실제 레이아웃과 비슷한 자리 표시.

- 실제 콘텐츠의 형태(아이콘 원 + 텍스트 바 2줄 등)를 흉내 낸다.
- 3~5개 반복 + 은은한 shimmer 애니메이션.
- 로딩 완료 시 레이아웃 시프트가 없어야 한다 (스켈레톤과 실제 행의 높이 일치).

## SegmentedControl / Tab

- SegmentedControl: 2~4개 상호배타 옵션 전환 (라디오 의미). `role="radiogroup"`.
- Tab: 화면 내 콘텐츠 영역 전환. 항목 많으면 가로 스크롤(fluid). `role="tablist"`, 알림 뱃지(red dot) 지원.
- 둘 다 선택 상태가 색+웨이트로 명확해야 한다.

## Switch / Checkbox

- Switch: 즉시 적용되는 on/off. `role="switch"` + `aria-checked`. 라벨과 함께 (무엇을 켜는지).
- Checkbox: 폼 제출 전 선택. 동의 목록은 "전체 동의" + 개별 항목(필수/선택 구분 뱃지) 패턴.
- 터치 영역은 라벨 텍스트까지 포함해 44px 이상.

## Badge (상태 뱃지)

- variant: `fill`(진한 강조) / `weak`(연한 배경 + 진한 글자, 기본 권장).
- 색상은 의미 체계 고정: 파랑=정보/진행, 초록=성공, 빨강=경고/중요, 노랑/주황=대기.
- 한 화면에 강조 배지 색상 3가지 이상 남발 금지.

## EmptyState / Result (빈 상태·결과 화면)

- 구성: figure(이모지/아이콘/일러스트) + title(상황, 해요체) + description(다음 행동) + (선택) 버튼.
- 성공/실패 결과 화면도 동일 구조 — 실패 화면일수록 재시도 버튼과 친절한 설명 필수.

## ProgressBar / Stepper

- 긴 작업(업로드·생성·심사)은 진행률 바(0~1) 또는 단계 스텝퍼로 현재 위치를 보여준다.
- 진행률 변경은 애니메이션으로 부드럽게.
- 다단계 폼은 상단에 ProgressStepper (현재 단계 강조, 완료 단계 체크).

## 반응형·세이프에어리어 (공통)

- 노치·카메라 홀·홈 바 → 세이프에어리어 패딩 처리 (`env(safe-area-inset-*)`).
- 실제 픽셀 해상도 기준으로 좌표 계산하지 않는다 — 논리 해상도(뷰포트) 기준 하나로 설계하고 에셋만 1x/2x 대응.
- 터치 기기 대응: hover에만 의존하는 인터랙션 금지.
- 테스트: 화면 비율이 다른 기기 2~3종 + 세이프에어리어 큰 기기 1종 + 작은 화면 1종.

## 접근성 요약표

| 컴포넌트 | 필수 처리 |
|---|---|
| 아이콘 버튼 | `aria-label` |
| 로딩 버튼 | `aria-busy` |
| Switch | `role="switch"`, `aria-checked` |
| SegmentedControl | `role="radiogroup"` / `radio` |
| Tab | `role="tablist"` / `tab`, `aria-selected` |
| Toast | `aria-live` |
| Dialog/Sheet | 포커스 트랩, 배경 `aria-hidden` |
| 아코디언 | `aria-expanded` |
| 장식 이미지 | `alt=""` |
