# 10가지 UX 법칙 — 설계·리뷰 체크리스트

> 원전: 존 야블론스키 ≪UX/UI의 10가지 심리학 법칙≫, 토스 앱 사례 기반.
> UI 작성 전 체크리스트, 코드 리뷰 기준, 컴포넌트 설계 원칙으로 사용한다.
> 체크리스트는 React/React Native/일반 웹 어디든 적용된다.

---

## 1. 제이콥의 법칙 (Jakob's Law)

> 사용자는 다른 서비스에서 축적한 경험으로 새 프로덕트를 판단한다.

- 동종 서비스의 표준 화면 구조를 따른다 (예: 커머스라면 목록 → 상세 → 장바구니 → 결제).
- 완전히 새로운 인터랙션은 사용자가 처음부터 학습해야 한다. 멘탈 모델을 깨야 할 명확한 이유가 없으면 **익숙한 패턴을 유지**한다.

**체크리스트**
- [ ] 핵심 플로우가 동종 서비스의 표준 순서를 따르는가?
- [ ] 탭/메뉴 구성이 사용자가 예상할 위치에 있는가?
- [ ] 아이콘이 통용되는 의미로 쓰였는가? (하트=찜, 돋보기=검색)

---

## 2. 피츠의 법칙 (Fitts's Law)

> 목표물에 도달하는 시간은 거리와 크기에 비례한다.

- **터치 타깃 최소 44×44px** (Apple HIG 기준). 시각적 크기가 작아도 터치 영역은 44 이상 확보.
- 버튼·칩·아이콘 간격 **최소 8px** — 특히 반대 의미의 버튼(삭제/저장)은 붙여두지 않는다.
- 자주 쓰는 핵심 액션은 엄지가 닿기 쉬운 **화면 하단**에 둔다.
- 리스트는 세로로 나열해야 시선 흐름·스크롤과 맞는다.

**체크리스트**
- [ ] 칩/선택지 버튼 총 높이 ≥ 44px? (`paddingVertical ≥ 11` 기준)
- [ ] 아이콘 버튼의 터치 영역이 아이콘보다 크게 잡혀 있는가?
- [ ] 파괴적 버튼과 확정 버튼 사이 간격이 충분한가? (missclick 위험)
- [ ] 핵심 CTA가 화면 하단에 있는가?

```jsx
// ❌ 너무 작음 (총 높이 약 30px)
chip: { paddingVertical: 7, paddingHorizontal: 12 }

// ✅ 최소 기준 (총 높이 약 44px)
chip: { paddingVertical: 11, paddingHorizontal: 14 }
```

---

## 3. 힉의 법칙 (Hick's Law)

> 선택지가 많아질수록 결정 시간과 인지 부하가 증가한다.

- 한 화면에 노출되는 선택지는 **7개 이하**.
- 넘으면 **그룹핑**하거나 단계를 나눈다 (progressive disclosure).
- 전문 용어가 필요한 선택지(임계값, 파라미터 등)에는 비전문가용 레이블/설명을 붙인다.

**체크리스트**
- [ ] 한 화면의 칩/옵션이 7개를 넘지 않는가?
- [ ] 넘는다면 카테고리로 묶거나 "더 보기"로 접었는가?
- [ ] 어려운 선택지에 설명이 붙어 있는가?

---

## 4. 밀러의 법칙 (Miller's Law)

> 작업 기억에는 7(±2)개 항목밖에 저장하지 못한다.

- 한 섹션의 목록은 **5~9개** 이내, 넘으면 "더 보기"로 접는다.
- 숫자는 **청킹**: `₩74,330` (O) / `74330` (X), `82%` (O) / `0.82` (X), `010-1234-5678`.
- 관련 정보는 카드/섹션으로 묶어 하나의 덩어리로 인식되게 한다.

**체크리스트**
- [ ] 금액에 통화 기호 + 천 단위 콤마가 있는가?
- [ ] 비율이 백분율로 표시되는가?
- [ ] 긴 목록이 섹션 제목으로 구분되어 있는가?

---

## 5. 포스텔의 법칙 (Postel's Law)

> 입력은 관대하게 수용하고, 요구하는 입력량은 보수적으로 줄여라.

- **1 thing / 1 page**: 하나의 화면(또는 시트)에는 하나의 목적만.
- 시스템이 추론할 수 있는 값은 자동으로 채운다 (주소 검색, 형식 자동 변환).
- 입력은 관대하게 받는다: 공백·하이픈 섞인 카드번호, 대소문자 섞인 이메일 전부 정규화해서 수용.

**체크리스트**
- [ ] 이 화면에서 사용자에게 묻는 것이 정말 하나(또는 최소)인가?
- [ ] 모든 선택 항목에 합리적인 기본값이 있는가?
- [ ] 입력값 정규화(trim, 하이픈 제거 등)를 하고 있는가?

---

## 6. 피크엔드의 법칙 (Peak-End Rule)

> 사용자는 경험 전체가 아니라 절정과 마지막 순간의 감정으로 판단한다.

- **오류·실패·빈 화면**이 가장 기억에 남는 순간이다. 차가운 시스템 메시지 대신 따뜻한 문구를 쓴다.
- 성공 순간(완료, 저장, 결제)에는 짧은 긍정 피드백을 준다.
- 빈 상태는 텍스트 한 줄로 끝내지 말고 **아이콘/이모지 + 상황 설명 + 다음 행동**으로 구성한다.

**체크리스트**
- [ ] 빈 화면이 "아이콘 + ~없어요 + 하면 나타나요" 구조인가?
- [ ] 에러 메시지가 해요체 + 긍정형인가?
- [ ] 완료 순간에 토스트/애니메이션 등 피드백이 있는가?

```jsx
// ❌ 차가운 빈 상태
<Text>보유 항목이 없습니다</Text>

// ✅ 따뜻한 빈 상태
<View style={styles.emptyState}>
  <Text style={styles.emptyIcon}>📭</Text>
  <Text style={styles.emptyTitle}>아직 담은 항목이 없어요</Text>
  <Text style={styles.emptyDesc}>마음에 드는 것을 담으면 여기에 나타나요</Text>
</View>
```

## 7. 테슬러의 법칙 (Tesler's Law)

> 모든 시스템에는 줄일 수 없는 복잡성이 있다. 그 복잡성은 사용자가 아닌 시스템이 흡수해야 한다.

- 복잡한 설정(파라미터, 임계값, 옵션 조합)은 시스템이 최적 기본값을 제안하고, 사용자는 필요할 때만 조정한다.
- 원시 데이터(확률 0.82, 상태 코드)를 그대로 보여주지 말고 해석된 결과(82%, "추천")로 번역한다.

**체크리스트**
- [ ] 사용자가 손대지 않아도 되는 합리적 기본값이 있는가?
- [ ] 원시 값이 아니라 해석된 의미를 보여주는가?
- [ ] 켜고 끄는 상태가 현재 설정 요약과 함께 표시되는가?

---

## 8. 심미적 사용성 효과 (Aesthetic-Usability Effect)

> 보기 좋은 디자인이 더 사용하기 편하다고 인식된다.

- 배경 `#f7f9fc` / 카드 `#ffffff` / 텍스트 `#191f28`의 깔끔한 계층 유지.
- 그림자는 미묘하게(`opacity 0.05~0.08`), 모서리는 둥글게(`borderRadius 16~24`).
- 포인트 컬러는 `#3182f6` **하나로** 일관성 유지.

**체크리스트**
- [ ] 카드의 그림자·radius가 화면 전체에서 일관적인가?
- [ ] 의미 색상(에러 `#f04452`, 성공 `#03b26c`)이 통일되어 있는가?
- [ ] 텍스트 계층(primary/secondary/tertiary)이 일관적인가?

---

## 9. 폰 레스토프 효과 (Von Restorff Effect)

> 비슷한 것들 중 가장 색다른 것만 기억에 남는다.

- 가장 중요한 CTA 하나만 fill(채운) 스타일로 차별화하고, 나머지는 weak/텍스트 버튼.
- 상태 배지는 색으로 구분하되, 강조 색이 한 화면에 3가지 이상 동시에 나오면 남용이다.
- **모든 것을 강조하면 아무것도 강조되지 않는다.**

**체크리스트**
- [ ] 화면당 fill CTA가 1개인가?
- [ ] 상태 배지 색상 체계가 화면 간 일관적인가?
- [ ] 강조 요소가 정말 "가장 중요한 것"에만 붙어 있는가?

---

## 10. 도허티 임계 (Doherty Threshold)

> 몰입을 유지하려면 0.4초 이내에 피드백을 제공해야 한다.

- 데이터 로딩은 **스켈레톤 UI**로 레이아웃 자리를 잡는다. 전체 화면 스피너만 쓰면 사용자는 빈 화면을 본다.
- 버튼 클릭 즉시 인라인 로딩 상태로 전환한다.
- 긴 작업(생성, 학습, 업로드)은 단계별 **진행률**을 보여준다.

**체크리스트**
- [ ] 리스트 로딩 시 스켈레톤이 표시되는가?
- [ ] 버튼에 loading 상태가 있고 클릭 즉시 반응하는가?
- [ ] 긴 작업에 진행률/단계 표시가 있는가?
- [ ] pull-to-refresh 인디케이터가 브랜드 색상인가?

```jsx
// ❌ 빈 화면 + 스피너만
{loading && <ActivityIndicator />}

// ✅ 스켈레톤으로 레이아웃 유지
{loading
  ? [1, 2, 3].map((i) => <SkeletonRow key={i} />)
  : items.map((item) => <ItemRow key={item.id} item={item} />)}
```
