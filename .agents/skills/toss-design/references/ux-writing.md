# UX 라이팅 가이드 — 토스 보이스톤

사용자에게 노출되는 모든 문구(버튼, 제목, 에러, 토스트, placeholder, 빈 상태, 푸시)에 적용한다.
목표는 "은행 창구 직원의 정중함"이 아니라 **"옆자리의 똑똑한 동료가 말해주는 느낌"**이다.

## 1. 해요체 — 상황·맥락 불문

격식체(~습니다)와 반말을 쓰지 않는다. 법적 고지문 같은 예외를 제외하면 전부 해요체.

| X | O |
|---|---|
| 저장되었습니다 | 저장했어요 |
| 로그인이 필요합니다 | 로그인이 필요해요 |
| 삭제하시겠습니까? | 삭제할까요? |

## 2. 능동적으로 말하기

'~었', '~되'가 들어간 수동 표현을 능동으로 바꾼다. 주어(서비스 또는 사용자)가 직접 행동한 것처럼 쓴다.

| X | O |
|---|---|
| 전송이 완료됐어요 | 전송했어요 |
| 계좌가 개설되었어요 | 계좌를 만들었어요 |
| 인증이 실패되었어요 | 인증하지 못했어요 |

## 3. 긍정적으로 말하기

"안 돼요/없어요/불가능해요"로 끝내지 말고, **어떻게 하면 되는지**를 말한다.
에러 메시지일수록 이 규칙이 중요하다 — 막힌 순간이 가장 기억에 남기 때문(피크엔드).

| X | O |
|---|---|
| 잔액이 부족해서 송금할 수 없어요 | 10,000원을 더 채우면 보낼 수 있어요 |
| 아직 사용할 수 없는 기능이에요 | 곧 만나볼 수 있어요. 준비 중이에요 |
| 잘못된 비밀번호입니다 | 비밀번호가 달라요. 다시 확인해 주세요 |
| 네트워크 에러 발생 | 잠시 연결이 어려워요. 조금 뒤에 다시 시도해 주세요 |

**다이얼로그 버튼 규칙**: 왼쪽(보조) 버튼은 **"닫기"**. "취소"는 부정적 뉘앙스라 쓰지 않는다.
오른쪽(주) 버튼은 행동을 그대로 쓴다: "삭제하기", "보내기", "나가기".

## 4. 캐주얼한 경어 — 과공은 비례

존대는 유지하되, 과도한 높임 표현을 걷어낸다.

| X | O |
|---|---|
| 확인하시겠어요? / 진행하시겠습니까? | 확인할까요? / 진행할까요? |
| 잠시만 기다려 주시기 바랍니다 | 잠시만 기다려 주세요 |
| 고객님께 안내드립니다 | ○○님에게 알려드려요 |
| 계신, 여쭤볼게요 | 있는, 확인할게요 |

## 5. '{명사}+{명사}' 쓰지 않기

한자어 명사를 겹쳐 쓰면 관공서 문서가 된다. 동사로 풀어쓴다.
풀기 어려우면 `{명사}가/를 {동사}해서` 형태로 변환한다.

| X | O |
|---|---|
| 계좌 개설 완료 | 계좌를 만들었어요 |
| 본인 인증 필요 | 본인인지 확인이 필요해요 |
| 조회 결과 없음 | 검색 결과가 없어요. 다른 단어로 찾아볼까요? |
| 송금 한도 초과 | 한도보다 큰 금액이에요. 100만 원까지 보낼 수 있어요 |

## CTA 버튼 라벨

- 누르면 무슨 일이 일어나는지 라벨만 보고 알 수 있어야 한다 (다크패턴 방지 정책의 필수 항목).
- "확인", "OK", "예" 같은 무색무취 라벨 대신 **"가입하기", "삭제하기", "1,000원 보내기"**처럼 행동/결과를 쓴다.
- 금액·수량이 정해져 있으면 라벨에 포함하면 더 좋다: "3개 담기", "₩12,000 결제하기".

## 상황별 템플릿

| 상황 | 형태 | 예시 |
|---|---|---|
| 빈 상태 | 상황 + 다음 행동 | "아직 주문한 내역이 없어요" + "첫 주문을 하면 여기에 나타나요" |
| 성공 토스트 | 한 일 그대로 | "링크를 복사했어요" |
| 파괴적 액션 확인 | 결과 고지 + 행동 버튼 | "메모 3개를 삭제할까요? 삭제하면 되돌릴 수 없어요" [닫기] [삭제하기] |
| 입력 도움말 | 형식 안내 | "8자 이상, 숫자를 포함해 주세요" |
| 로딩(장시간) | 무엇을 하는 중인지 | "결제를 확인하고 있어요…" |

## 셀프 체크

문구를 쓴 뒤 이 네 가지를 순서대로 확인한다:

1. 해요체인가?
2. '~었/되/시겠' 없는가?
3. 부정형으로 끝나는 문장이 있다면, "어떻게 하면 되는지"로 바꿀 수 있는가?
4. 명사만 나열된 라벨이 있는가? (있다면 동사로)
