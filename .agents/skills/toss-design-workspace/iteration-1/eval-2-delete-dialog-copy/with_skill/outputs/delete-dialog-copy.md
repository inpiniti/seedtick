# 삭제 확인 모달 문구 개선안

## 현재 → 개선

| 요소 | 현재 | 개선 |
|---|---|---|
| 제목 | 경고 | **삭제할까요?** (대상을 알면 "메모를 삭제할까요?"처럼 구체적으로) |
| 내용 | 정말 삭제하시겠습니까? 삭제된 데이터는 복구가 불가능합니다. | **삭제하면 되돌릴 수 없어요.** |
| 보조 버튼 | 취소 | **닫기** |
| 주 버튼 | 확인 | **삭제하기** (경고색 `#f04452`) |

### 개선 후 모습

> **삭제할까요?**
> 삭제하면 되돌릴 수 없어요.
>
> [ 닫기 ] [ **삭제하기** ]

대상이 특정되면 제목에 그대로 담는 것이 가장 좋아요.

> **메모 3개를 삭제할까요?**
> 삭제하면 되돌릴 수 없어요.
>
> [ 닫기 ] [ **삭제하기** ]

## 왜 이렇게 바꿨나

1. **제목 '경고' → 질문형 제목** — '경고'는 명사 라벨이고, 무엇을 결정해야 하는지 알려주지 않아요. 제목만 읽어도 상황을 알 수 있게 "○○을 삭제할까요?"로 바꿨어요. 오류가 아닌 확인 상황에 경고 프레임을 씌우는 것은 상황과 어긋난 시각 신호이기도 해요.
2. **"~하시겠습니까" → 해요체 + 캐주얼한 경어** — "삭제하시겠습니까?"는 격식체·과공 표현이라 "삭제할까요?"로. "정말"은 이미 확인 모달이라는 형식이 전달하므로 뺐어요.
3. **"복구가 불가능합니다" → "되돌릴 수 없어요"** — 수동·한자어 표현('복구 불가능')을 걷어내고 결과를 한 문장으로 고지했어요. 파괴적 액션 확인의 표준 형태는 "결과 고지 + 행동 버튼"이에요.
4. **"취소" → "닫기"** — 다이얼로그 왼쪽(보조) 버튼은 항상 "닫기". "취소"는 부정적 뉘앙스라 쓰지 않아요.
5. **"확인" → "삭제하기"** — 라벨만 보고 누르면 무슨 일이 생기는지 알 수 있어야 해요. 무색무취한 "확인"으로 파괴적 액션을 실행시키는 것은 불명확한 CTA(다크패턴)예요.

## 구현 체크리스트

- 확인(주) 버튼은 경고색 `#f04452`, 보조 버튼은 weak variant — 화면당 강조 버튼은 하나만.
- 버튼 터치 타깃 ≥ 44px, 인접 버튼 간격 8px 이상.
- 딤(dim) 클릭으로 닫기 허용이 기본. 열릴 때 다이얼로그로 포커스 이동, 배경에 `aria-hidden` + 포커스 트랩.
- 삭제 완료 후에는 짧은 긍정 피드백: 토스트 "삭제했어요" (3초 자동 닫힘).
- 삭제 대상 수량을 알면 제목에 포함: "메모 3개를 삭제할까요?"
