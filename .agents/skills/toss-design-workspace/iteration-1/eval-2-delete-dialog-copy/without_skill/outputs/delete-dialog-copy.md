# 삭제 확인 모달 문구 개선안

## 현재 상태

| 요소 | 현재 문구 |
|---|---|
| 제목 | 경고 |
| 내용 | 정말 삭제하시겠습니까? 삭제된 데이터는 복구가 불가능합니다. |
| 버튼 | [취소] [확인] |

## 문제점 진단

1. **제목 "경고"가 정보를 주지 않음** — 무엇에 대한 경고인지 알 수 없고, 시스템 오류처럼 느껴져 불필요한 불안감을 줍니다. 제목이 곧 질문/행동을 담아야 사용자가 본문을 읽지 않아도 상황을 파악할 수 있습니다.
2. **"확인" 버튼이 모호함** — 삭제라는 파괴적(destructive) 행동을 수행하는 버튼인데 라벨이 "확인"이라, 무엇을 확인하는지 불분명합니다. 습관적으로 "확인"을 눌러 실수로 삭제할 위험이 큽니다. 버튼 라벨은 결과 행동을 그대로 써야 합니다.
3. **딱딱한 문어체** — "~하시겠습니까", "불가능합니다"는 격식은 있지만 위압적입니다. 이중 부정에 가까운 "복구가 불가능합니다"보다 "복구할 수 없어요"가 더 즉시 이해됩니다.
4. **"정말"이라는 강조어** — 사용자를 다그치는 인상을 줍니다. 결과(복구 불가)를 명확히 알려주면 강조어 없이도 충분히 신중해집니다.

## 개선안 (권장)

| 요소 | 개선 문구 |
|---|---|
| 제목 | 삭제할까요? |
| 내용 | 삭제한 데이터는 다시 복구할 수 없어요. |
| 버튼 | [취소] **[삭제]** |

### 개선 포인트

- **제목이 곧 질문**: "삭제할까요?" 한 줄로 상황과 요구되는 결정을 동시에 전달합니다.
- **버튼 = 행동**: 확인 버튼을 "삭제"로 바꿔, 누르면 무슨 일이 일어나는지 버튼만 봐도 알 수 있게 합니다. 제목("삭제할까요?")과 버튼("삭제")이 짝을 이룹니다.
- **결과를 담백하게 고지**: 협박하듯 경고하지 않고, 되돌릴 수 없다는 사실만 정확히 알려줍니다.
- **부드러운 구어체**: "~할까요?", "~없어요"로 톤을 낮추되 정보량은 유지합니다.

### 삭제 대상을 명시할 수 있다면 (더 권장)

대상 이름을 알 수 있는 화면이라면 제목에 넣어주는 것이 가장 좋습니다.

| 요소 | 개선 문구 |
|---|---|
| 제목 | '{항목 이름}'을(를) 삭제할까요? |
| 내용 | 삭제하면 다시 복구할 수 없어요. |
| 버튼 | [취소] **[삭제]** |

예: `'2025년 매매일지'를 삭제할까요?` — 사용자가 엉뚱한 항목을 지우는 실수를 한 번 더 걸러줍니다.

## UI 처리 가이드 (문구 외)

- **삭제 버튼은 위험 색상(red)으로**: 파괴적 행동임을 시각적으로도 구분합니다. 취소는 중립(회색/보조) 스타일.
- **버튼 순서 유지**: [취소]가 왼쪽, [삭제]가 오른쪽(주 행동 위치). 다만 기본 포커스(Enter)는 [취소]에 두어 실수 삭제를 방지합니다.
- **모달 바깥 클릭/ESC = 취소**: 파괴적 확인 모달에서 바깥 클릭은 항상 취소로 처리합니다.
- **대량/중요 데이터라면 한 단계 더**: 복구가 절대 불가능한 대량 삭제(계정, 전체 기록 등)는 항목 이름 입력 확인 같은 추가 안전장치를 고려합니다. 일반 항목 삭제에는 과합니다.
